# Tour Guides

This document is a plain markdown guide for where `Tour` should be used in the app. Each section describes a screen a user can reasonably reach from the front page, plus the short tutorial that screen should show.

The rule is simple: keep each tour short, focused, and tied to what the user can do on that screen.

Every tour should have a desktop version and a mobile version. Mobile tours should usually use fewer steps and shorter copy.

For screens that require an account, the first tour step should point at the login/register button and explain where to sign in.

## Home

Use this tour on the front page.

Tell the user:

- this app collects marketplace content from more than one source
- the main sections are jobs, companies, products and services, ventures, tribes, and posts
- they can start by opening any section that looks interesting
- search, filters, and featured cards help them decide where to go next
- they can share interesting pages from here or save them for later by opening the right detail page

Keep it short. The home page should orient people, not teach every feature at once.

## Jobs List

Use this tour on the jobs listing page.

Tell the user:

- this page lists available jobs from one or more sources
- they can open a job card to see the full detail page
- they can use search or filters to narrow the list
- if the app supports identity-based browsing here, show how to find jobs by identity or source
- returning users should know this page is for scanning, not applying yet
- if the list shows share or like controls, explain that those are quick ways to react before opening the detail page

## Job Detail

Use this tour on an individual job page.

Tell the user:

- this is the full job description
- they can read the role, requirements, and posting context
- they can follow related links back to the company or source identity
- they can comment or otherwise react if the page supports it
- they can share the job with someone else if the share action is visible
- if there is an edit action, show that only the owner or editor should use it

## Job Create or Edit

Use this tour on the job form.

Tell the user:

- this form is for creating a new job or updating an existing one
- the title and description are the main fields
- any extra fields should help applicants understand the role
- save or publish is the final action
- if there are preview or cancel actions, explain them briefly

## Companies List

Use this tour on the companies listing page.

Tell the user:

- this page groups companies from the network
- they can open a company card to reach the company detail page
- they can use search to find a company by name or source identity
- this page is for discovery and comparison
- if the app supports sorting or filters, call those out here
- if the card exposes share or like actions, mention that those are quick ways to react without leaving the list

## Company Detail

Use this tour on an individual company page.

Tell the user:

- this page shows the company profile and related content
- they can open posts, products, jobs, or venture links connected to the company
- they can follow updates, read comments, and see the company’s public story
- they can like or share the company if those actions are available
- if the page supports posting from the company context, explain that too
- this is the best place to understand who the company is before acting

## Company Create or Edit

Use this tour on the company form.

Tell the user:

- this form is for setting up a company page or updating an existing one
- the name, description, and identity links are the core pieces
- any logo, contact, or metadata fields should be explained briefly
- saving here updates the company listing the rest of the app shows
- remind the user this is where they keep the public company identity current

## Products and Services List

Use this tour on the products and services listing page.

Tell the user:

- this page shows product and service listings from the network
- they can open an item to see pricing, description, and seller details
- they can filter or search if the interface supports it
- buyers use this page to compare items before opening a detail page
- returning users should know this is the main browsing entry for shopping
- if quick actions are shown, mention like and share first because they are the fastest ways to react to an item

## Product Detail

Use this tour on a product detail page.

Tell the user:

- this page shows the full product or service view
- they can like the item, comment on it, and inspect the seller context
- they can open related company or identity pages from here
- if the product can be bought, show where the buy or add-to-cart action lives
- they can share the product if the page shows a share button
- this is where a curious user becomes a buyer

## Product Create or Edit

Use this tour on the product form.

Tell the user:

- this form is for creating a product or service listing
- the main fields should describe what is being sold, how much it costs, and who it belongs to
- images or supporting details should make the listing easier to trust
- save/publish is the final step
- edits should be used when price, availability, or description changes

## Ventures List

Use this tour on the ventures listing page.

Tell the user:

- this page shows venture ideas and venture listings
- users can open a venture to read the full story
- they can use the page to compare early-stage ideas or active ventures
- if the page has search or filters, explain those as a quick way to narrow the list
- if the list shows like or share controls, explain those as fast ways to react before opening the detail page
- this page is for discovery, not deep editing

## Venture Detail

Use this tour on an individual venture page.

Tell the user:

- this page explains the venture in full
- users can read the pitch, follow links, and see related comments or posts
- they can move from the venture to its company or identity context if that is available
- this is a good place to show engagement actions like like and comment
- if the venture shows join or leave controls, explain that the user can join the venture when they want to take part and leave when they no longer want to be involved
- if a share action is available, point it out as a quick way to spread the venture story
- if there is a related posting trail, explain that the venture story can be followed through the app

## Venture Create or Edit

Use this tour on the venture form.

Tell the user:

- this form is for creating or updating a venture
- the short pitch, description, and supporting detail are the important parts
- users should understand that this is where they shape the public story
- saving publishes the updated venture to the network
- if there are optional fields, keep the explanation light

## Tribes and Identities List

Use this tour on the tribes or identity listing page.

Tell the user:

- this page helps people look up identities in the network
- they can use it to find companies, people, or groups connected to an identity
- it is a discovery page for browsing who is active in the marketplace
- if filters or search are available, show how to use them to find a known identity quickly
- this page should make it clear that identity is the organizing layer behind many listings

## Tribe or Identity Detail

Use this tour on an individual tribe or identity page.

Tell the user:

- this page shows the identity profile and what it is connected to
- users can open related companies, posts, or listings from here
- this is where someone learns how a group or identity participates in the network
- if the page has comments or reactions, point those out as social signals
- this page is especially useful when a user wants to trace content back to a source

## Posts List

Use this tour on the posts listing page.

Tell the user:

- this page shows updates, announcements, and shared posts
- users can open a post to read the full thread or discussion
- they can use it to follow company updates, venture updates, or general news
- if filters or search are available, explain how to narrow the feed
- if the post card shows like or share controls, explain them as the quickest actions on the feed
- this page is for reading and discovery, not editing yet

## Post Detail

Use this tour on a post page.

Tell the user:

- this page shows the full post and its discussion
- users can like the post, comment on it, and follow linked content
- they can jump from the post to a related company, job, product, venture, or identity
- they can share the post if the share action is visible
- this is the best place to show the social part of the app
- if edit actions exist, explain that they are for the post owner or editor

## Post Create or Edit

Use this tour on the post form.

Tell the user:

- this form is for writing an announcement or update
- the post should be short, clear, and tied to the right company or identity
- users can add context so readers know where the post belongs
- saving publishes the post to the network
- editing is how the author keeps the post current

## Profile

Use this tour on the profile page.

Tell the user:

- this page is for personal account information
- users can update their name, links, and other profile details
- if wallets, identities, or company connections are present, explain them here
- this is the place to keep the user’s public presence current
- if the app has preference settings, point them out as a final step

## Profile Wallets

Use this tour inside the profile page for the wallet section.

- This section is where payment wallets are added and ordered.
- The top wallet is preferred first during checkout.
- Use the add button when you want another wallet entry.
- Move and remove controls help keep the list tidy.

## Profile Address

Use this tour inside the profile page for the shipping address section.

- This section stores the shipping address used during checkout.
- The search button helps you look up an address when autocomplete is available.
- The manual fields let you finish the address yourself.
- The reset action clears the saved address if it needs to change.

## Publish

Use this tour on the publish page.

Tell the user:

- this page is where the user chooses what kind of thing they want to publish
- they can create posts, jobs, companies, products, or ventures depending on what the app supports
- the page should help them choose the right content type quickly
- once they choose, the matching form should feel obvious
- this is the main launch point for creating new content
- if the user is coming from a shared link or a liked item, mention that publish can also be used to continue the story with a new post

## Publish Forms

Use a short form tour on each create screen that opens from Publish.

- Job form: show the title field first, then the company selector, then the publish and draft buttons.
- Company form: show the company name field first, then the tribe selector, then the publish and draft buttons.
- Product form: show the product name and price first, then the company selector, then the publish and draft buttons.
- Post form: show the title and content fields first, then the company selector, then the publish and draft buttons.
- Venture form: show the venture name and description first, then the stage and resources, then the publish and draft buttons.

## Cart

Use this tour on the cart page.

Tell the user:

- this page shows what the buyer has selected
- users can review items, quantities, and totals before placing an order
- they can go back if they want to adjust what is in the cart
- this page should make the final purchase step feel safe and clear
- if the app supports removing items, explain that here too

## Order

Use this tour on the order page.

Tell the user:

- this page is the checkout and payment flow
- users can confirm what they are buying and how they want to pay
- if there are wallet choices, show where those decisions happen
- this is the last step before completion
- after payment, users should know where the success state or next screen appears

## Syndication

Use this tour on the syndication list or network page.

Tell the user:

- this page shows the available syndication sources
- users can inspect where data is coming from
- they can open a source to see more detail
- this page is useful for people who care about how the marketplace is connected
- it should make the network feel understandable, not mysterious

## Syndication Detail

Use this tour on a single syndication source page.

Tell the user:

- this page shows one source in full
- users can see the source address, related content, and any available metadata
- this is where they verify that a source is real and useful
- if the page supports opening the source in a browser or copying its address, explain that briefly
- this page is the detail view for the network itself

## Syndicate Setup

Use this tour on the `/syndicate` onboarding route.

Tell the user:

- this walkthrough helps them get a marketplace online
- the tour should cover the server recommendation, the script download, the installer, and the final browser step
- it should explain what to click without sounding technical
- the last page should make it clear that the user finishes setup in the browser
- this tour is for people who want to create a syndicated marketplace, not just browse one

## Detail Page Rules

On any detail page, the tour should usually mention:

- how to go back to the list
- where the comments or reactions live
- where the related links are
- what the page is for in one sentence

## Form Page Rules

On any create or edit form, the tour should usually mention:

- what kind of object is being created or changed
- which fields matter most
- what save or publish means
- whether the page is for a new item or for updating an existing one

## General Rule

Keep each tour short enough that it can be read quickly. The purpose is to help the user understand the screen they are on, not to teach the whole app at once.
