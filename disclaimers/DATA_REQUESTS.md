# Data Requests

This document explains how users can ask NSWAP about the personal data we control.

NSWAP is built as a federated frontend. In practice that means some information is handled by NSWAP itself, while some information lives on the third-party servers that the app connects to. When you send a request, we will handle the data we control directly and point you to the right server when the request needs to be completed elsewhere.

## What you can ask for

You can ask us to:

- Confirm whether we process personal data about you
- Give you a copy of the personal data we hold about you
- Correct inaccurate or incomplete data
- Delete data where deletion is possible
- Explain where a piece of data came from
- Explain whether a record is stored by NSWAP or by a connected server

## What kinds of data this may cover

Depending on how you use the app, a request may relate to:

- Your profile and account information
- Your display name, avatar, email address, or verification status
- Wallets, payment preferences, or shipping details stored in your profile
- Posts, comments, likes, subscriptions, and shares
- Listings, jobs, companies, ventures, and other published content
- Cart, order, or checkout information
- Server URLs or other routing data that identify where content came from
- Reports or support messages you send to us

## How to make a request

Please include enough detail for us to find the right record. Helpful information includes:

- The email address or login identity used in NSWAP
- The profile name or server name involved
- A link to the page, post, comment, or listing in question
- A short explanation of what you want us to do

You can send the request through the app or by the support contact method listed in our privacy notice.

## What happens after you send a request

1. We check that the request is legitimate
2. We identify which data NSWAP controls and which data belongs to a third-party server
3. We decide whether the request can be completed directly
4. If needed, we explain which part must be handled by another server
5. We reply in plain language and keep a record of the request and our response

## What we will tell you

When we reply, we will try to make it clear:

- What data we found
- Where the data came from
- Whether it is stored locally in NSWAP or on another server
- Whether we can delete, correct, or export it
- Whether some data must be retained for security, moderation, or legal reasons

## Federated content

Because NSWAP connects to more than one server, not every request can be completed in one place.

Examples:

- If the data is stored only in NSWAP, we can handle it directly
- If the data lives on a remote server, we may need to direct you to that operator or relay the request
- If the same data exists in more than one place, we may need to coordinate across those places

## Timing

We aim to respond as clearly and quickly as possible. If a request needs more time because it involves multiple servers or a large amount of data, we will explain that in our reply.

## Limits

We may not be able to delete or change data if:

- The data belongs to a third-party server we do not control
- The data must be retained for legal, security, or moderation reasons
- The request is not specific enough for us to identify the record
- The request would affect another user’s data or a record we are required to keep

## Good-faith use

Please use this process responsibly. Repeated abusive requests, fake identity claims, or attempts to access another person’s data may be refused.
